[configure.usage.server]
Aufruf:
  sudo ./liltress configure           Fragen, dann das Profil, dann die Installation
  sudo ./liltress configure --basic   Projektname + Domain; der Rest wird berechnet
  sudo ./liltress configure --avance  alle Fragen außer dem Serverprofil
  ./liltress check                    prüft die beiden Dateien, Code 0 wenn sie stimmen

Das Serverprofil (MATRIX, LIVEKIT, WIREGUARD) wird zu Beginn der Installation gefragt.

Beispielwerte:
  PROJECT_NAME             Liltress
  DOMAIN                   example.com
  MAIN_USER                drawbridge
  SSH_PORT                 2501
  MODE_TEST                0 (Produktion) oder 1 (Debug ohne Certbot)
  MODE_DEV                 1 (lokales Portal) oder 0 (GHCR-Images)
  POSTFIX_MAIL_ADDRESS     sie@example.com          (From, bei Alarmen)
  POSTFIX_MAIL_SMTP        smtp-mail.outlook.com:587
  WATCHDOG_MAIL            dieselbe Adresse wie From
  TURNSTILE_SITE_KEY       0x4AAAAAAAxxxxxxxxxx    (Profil MATRIX)
  POSTGRES_WEB_PASSWORD          openssl rand -hex 32    (Profil MATRIX, oder GEN)

Maschinenpasswörter (root, SSH, Postgres synapse, Keycloak, htpasswd)
werden hier nicht eingegeben. Der Installer erzeugt sie. Mit Alarmen sendet
er sie an From. Ohne Alarme hängt er sie an /root/liltress-credentials.txt an.
Die Kopie nach Google Drive ist wählbar. Ausgeschaltet wird rclone nicht installiert.
